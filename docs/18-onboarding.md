# 18 — Onboarding Specification

**Routes.** `/welcome` · `/auth/callback` · contextual first-run states

Onboarding has one job: get a user from arrival to a first understood action
without pretending the product is simpler or safer than it is.

```
┌ WELCOME ─────────────────────────────────────────────────────────────────┐
│  PrecisionEdge                                                           │
│  Analyse, trade, automate, and measure synthetic and financial markets   │
│  through your own Deriv account.                                         │
│                                                                          │
│  [ Connect Deriv account ]      [ Explore in read-only mode ]            │
│                                                                          │
│  You keep full control. PrecisionEdge never holds your funds and cannot  │
│  withdraw. Trading involves risk of losing your capital.                 │
└──────────────────────────────────────────────────────────────────────────┘
      │
      ▼ OAuth at Deriv ──▶ /auth/callback ──▶ account selection
┌ CHOOSE ACCOUNT ──────────────────────────────────────────────────────────┐
│ ● Demo  VRTC1234567  USD 10 000.00     recommended to start              │
│ ○ Real  CR1234567    USD 214.02                                          │
│ Demo is selected by default. You can switch at any time from the header. │
└──────────────────────────────────────────────────────────────────────────┘
```

## Flow

1. **Welcome** — what the product does, in one sentence, plus the risk
   statement. Two paths: connect, or explore read-only with public market data
   and no account features.
2. **OAuth** — the user authorises at Deriv (doc 20 and 21). Scopes requested
   are named on this screen before the redirect, with a one-line reason each.
3. **Callback** — tokens exchanged and stored, accounts enumerated, demo
   selected by default. Failure paths are explicit (denied, expired, mismatched
   state) and each offers a single recovery action.
4. **Orientation** — a three-card, dismissible strip on the dashboard: the loop
   (analyse → trade → automate → measure), where demo/real lives, and how to
   stop a bot. It is not a modal tour and does not block the interface.
5. **First actions** — contextual empty states across the product do the rest
   of the teaching, each explaining the screen it sits on.

## Progressive disclosure

Beginners see the dashboard, markets, analysis, and trader. Bots, the builder,
and backtesting are visible but marked as requiring a demo run first; the AI
strategy assistant is offered as an entry point. Nothing is hidden behind a
level system — the sequencing is advisory and stated, not enforced by locks the
user cannot reason about.

## Risk acknowledgement

Before the first real-money action (not before browsing), a single
acknowledgement names: capital at risk, that synthetic indices are simulated
instruments generated by Deriv, that automated strategies can lose money
quickly, and that past results do not determine future results. It is recorded
with a timestamp and never re-shown as a nag.

## Read-only mode

Without a connection the user can browse markets, view charts and indicators,
and use the digit analyser on public data. Every account-dependent surface
shows a consistent inline "connect to use this" affordance rather than a
disabled control with no explanation.

## States

OAuth denied → return to welcome with the reason. Token invalid on return →
re-auth prompt, no partial session. No real accounts on the Deriv profile →
demo only, stated as a fact rather than an error. Returning user → straight to
the dashboard, no re-onboarding.

## Mobile

The same sequence in a single column; the account chooser is a sheet, and the
orientation strip becomes a horizontally scrollable set of three cards.
